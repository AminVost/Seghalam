**وضعیت:** کد بازطراحی‌شده و تست خودکار TypeScript/SQLite موفق است؛ اجرای APK جدید روی گوشی‌های مختلف هنوز نیاز به تأیید دارد. اطلاعات کاربر نباید حذف شوند.

## تغییرات نسخه 0.3.0

- راست‌به‌چپ واقعی در ساختار صفحه‌ها، بازچینی ردیف‌ها و نوار پایین
- تایپوگرافی فارسی کوچک‌تر و منسجم‌تر، اصلاح ارتفاع ایموجی‌ها، تصاویر برند `contain` و حذف clipping در فهرست غذا
- تم روشن، تیره و هماهنگ با تنظیمات گوشی؛ ذخیره انتخاب در SQLite خود دستگاه
- تور تعاملی اختیاری با انیمیشن، امکان ردکردن و دسترسی دوباره از راهنما/تنظیمات
- انتخاب چندتایی مواد برای یخچال و فهرست خرید؛ ثبت تراکنشی بدون درج مقدار ساختگی
- صفحه خانه واضح‌تر با سه قدم شروع، برنامه‌ریزی و فهرست خرید
- کاتالوگ ۳۷۸ دستور همچنان از داده‌های آفلاین همراه اپ خوانده می‌شود، نه تراکنش سنگین در SQLite

**ساخت APK ویندوز:**

```powershell

powershell -ExecutionPolicy Bypass -File .\scripts\build-phone-apk.ps1 -UseMavenMirror
```

بعد از مشاهده `BUILD SUCCESSFUL`، خروجی `Seghalam-0.3.0-PHONE-TEST.apk` را **روی نسخه قبلی نصب** کن؛ Uninstall یا Clear Data نزن. گواهی Debug همان قبلی است. برای تغییرات سورس، تست‌های `npm run typecheck` و `npm run test:all` نیز در GitHub Actions اجرا می‌شوند.

**بازبینی کامل جریان‌ها و چک‌لیست تست روی گوشی:** [گزارش RTL و تجربه کاربری](docs/UX_RTL_REVIEW_2026-10-22_FA.md).

# سه‌قلم غذا | Seghalam — نسخه تست 0.2.0

> **به‌روزرسانی ۲۲ اکتبر ۲۰۲۶ (رفع خطای راه‌اندازی SQLite):** نسخه قبلی Android APK با موفقیت Build شد اما روی یک گوشی در اولین اجرا هنگام **واردکردن کاتالوگ غذا به SQLite** خطا داشت. اصلاح ساختاری جدید این ورود پرحجم را حذف کرده است: ۳۷۸ دستور پخت ثابت مستقیماً از بسته آفلاین برنامه خوانده می‌شوند؛ SQLite فقط داده‌های متغیر کاربر را ذخیره می‌کند. **APK اصلاح‌شده هنوز روی گوشی تست نشده است؛ تأیید اجرای واقعی باقی است.**
>
> اطلاعات نصب قبلی را **پاک نکنید**. برای تست تغییرات، با همان امضای Debug نسخه جدید را روی نسخه نصب‌شده نصب کنید.

### بروزرسانی و ساخت APK تستی روی Windows / PowerShell

```powershell
git pull origin main
npm run typecheck
npm run test:all
powershell -ExecutionPolicy Bypass -File .\scripts\build-phone-apk.ps1 -UseMavenMirror
```

فایل خروجی در صورت موفقیت Build: `Seghalam-0.2.0-PHONE-TEST.apk`. گزینه `-UseMavenMirror` فقط برای شبکه‌هایی است که دسترسی مستقیم به مخازن Gradle ندارند و از **مخزن شخص ثالث** استفاده می‌کند؛ اگر دسترسی رسمی برقرار است، آن گزینه را حذف کنید.

**تست‌ها:** ۷۴ تست Node شامل ۷ تست جدید کاتالوگ و ۲ تست با Mock راه‌اندازی SQLite، تست ساختاری داده و مهاجرت‌های SQLite میزبان موفق شدند. این‌ها آزمون واقعی Native روی همه دستگاه‌های اندرویدی نیستند. کاربر یک Build قبلی را با موفقیت انجام داده است؛ کد اصلاح‌شده هنوز نیازمند Build و تست مجدد روی گوشی است.

**جزئیات فنی:** [معماری دیتابیس](docs/DATABASE_SCHEMA.md) و [راهنمای ساخت Android](docs/GITHUB_CLONE_BUILD.md).

**محدودیت محتوا:** تمام ۳۷۸ دستور پخت همچنان در وضعیت `draft` و بدون تأیید مستقل آشپزی‌اند و نسخه هنوز برای انتشار عمومی تأیید نشده است.

# سه‌قلم غذا | Seghalam

**وضعیت: توسعه دیتابیس آفلاین انجام شده؛ نسخه آماده انتشار Production و APK تست‌شده هنوز وجود ندارد.**

اپ Android-first با React Native `0.87.1`، TypeScript strict و SQLite. هدف محصول: پیشنهاد غذا با مواد موجود در خانه، بدون الزام اینترنت/ثبت‌نام/API پولی. مشخصات اصلی در `docs/ORIGINAL_MASTER_PROMPT.txt` و گزارش قابلیت‌ها در `docs/IMPLEMENTATION_STATUS.md` است.

## دستاورد ارتقای دیتابیس — ۲۰ اکتبر ۲۰۲۶

- **۳۷۸ دستور متمایز** در مقابل ۱۷۲ قبلی، یعنی **۲۰۶ دستور جدید** (+۱۱۹٫۸٪، حدود ۲٫۲۰ برابر).
- **۲۳۶ ماده استاندارد** در مقابل ۱۵۸ قبلی؛ **۲۰۴۵ ردیف ارتباط ماده–دستور**.
- پوشش برچسب‌ها با هم‌پوشانی: ایرانی ۱۰۵، سبک ۱۸۱، میان‌وعده ۱۱۰، فست‌فود خانگی ۱۳۹.
- جست‌وجوی نرمال‌شده فارسی و Alias مواد در SQLite؛ ایندکس‌ها، `LIMIT/OFFSET` و ورود دسته‌ای با SQL پارامتردار؛ migration پایدار schema **v5**؛ نسخه محتوایی `2026102003`؛ داده‌های شخصی کاربر در جدول‌های مستقل حفظ می‌شوند.
- یک فایل SQL مستقل برای بازرسی (`content/seghalam-catalog.sqlite`، حدود ۱٫۵۲ MB)، خروجی JSON (`content/catalog.generated.json`) و صف بازبینی ۳۷۸ ردیفی (`content/editorial-review-queue.csv`).

## تفاوت «نام غذای یافت‌شده در وب» با «دستور پخت تأییدشده»

**تمام ۳۷۸ دستور `draft` هستند و هیچ‌کدام تأیید مستقل آشپزی ندارند.** برای ۲۰۶ دستور جدید نام غذا از فهرست‌های آنلاین ایرانی/خارجی شناسایی و نشانی مرجع ثبت شده، ولی مقدار مواد و مراحل پخت **تدوین/برآورد مستقلی** هستند؛ از دستور اصلی سایت استنساخ یا با آن بندبه‌بند تطبیق داده نشده‌اند. ۱۸۵ مورد از منابع جدید تنها لینک *مجموعه غذاها* دارند، ۸ مورد پیوند صفحه خاص دستور و ۱۳ مورد اقتباس هستند. ۱۶ دستور قدیمی URL موردی داشتند، اما اعتبار آن‌ها دوباره تأیید نشده است. **لینک یا شهرت سایت، تأیید مقدار مواد یا روش پخت نیست.**

- برای غذاهای پیچیده ایرانی، ۱۶ دستور جدید مراحل اختصاصی تدوینی دارند؛ بقیه عمدتاً مراحل راهنمای متناسب با روش پخت هستند و هنوز آموزش پخت معتبر/مورد تأیید کارشناس محسوب نمی‌شوند.
- متن‌های دارای حق نشر و عکس سایت‌های ثالث کپی نشده‌اند. حق استفاده از تصاویر، آلرژن‌ها، تغذیه، مقادیر و تطبیق با نام غذا نیاز به ممیزی مستقل دارد.
- افزودن رکوردها **گیت انتشار** را دور نمی‌زند: `npm run audit:content` عمداً تا تکمیل مدرک بازبینی انسانی رد می‌شود. بدون آن کاتالوگ نباید «غذاهای قابل اطمینان و تأییدشده» معرفی شود.

## مسیرهای مهم

- `content/researched-recipes.psv`: داده قابل ویرایش ۲۰۶ دستور جدید همراه لینک راهنما و مواد برآوردی.
- `content/culinary-specific-steps.psv`: مراحل اختصاصی ۱۶ دستور ایرانی.
- `scripts/compile_research_recipes.py`: تولید مجدد فایل TypeScript از داده‌های قابل ویرایش.
- `src/data/ingredients.ts` و `src/data/researchIngredients.ts`: مواد، نام‌های معادل و ترکیبات دارای برچسب نامطمئن.
- `src/storage/db.ts`: migration v5، واردکردن دسته‌ای، جست‌وجوی SQL و کش محتوای آفلاین.
- `docs/DATABASE_EXPANSION_REVIEW_2026-10-20.md`: اعداد، منشأ، ارزیابی عملکرد، تست و موانع.
- `docs/CONTENT_RESEARCH_2026-10-20.md`: گزارش **تاریخی** قبل از این ارتقا؛ برای اعداد جدید گزارش فوق را بخوانید.

## ساخت داده، اعتبارسنجی و تست

پیش‌نیاز تست مستقل: Node 22، TypeScript compiler و Python 3.

```bash
python scripts/compile_research_recipes.py
npm run test:all
python scripts/export_review_queue.py
python scripts/profile_catalog_sqlite.py
npm run audit:content  # EXPECTED FAILURE: 378 unreviewed content drafts
```

تست‌های دامنه و منطق: **۶۲ تست موفق، ۰ ناموفق**؛ QA ساختاری، DDL و ارتباط خارجی SQLite موفق. بنچمارک SQLite روی سیستم میزبان به‌جای گوشی اجرا شده و معادل عملکرد React Native یا اندروید نیست. برای آخرین شواهد `docs/TEST_REPORT.md` و `docs/CATALOG_SQLITE_HOST_BENCHMARK.json` را ببینید.
