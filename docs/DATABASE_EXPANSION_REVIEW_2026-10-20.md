## معنای دقیق «برگرفته از سایت معتبر»

نام دستورهای جدید از فهرست‌ها/صفحات غذا در سایت‌هایی مانند **Good Food** و **چی‌شی** شناسایی شده و متن و تصاویر طرف ثالث کپی نشده‌اند. داده جدید `content/researched-recipes.psv` شامل نام فارسی، نام اصلی/مرجع، دسته، زمان پیشنهادی، مواد، مقادیر تدوینی و روش طبخ است. `scripts/compile_research_recipes.py` آن را به ساختار برنامه تبدیل می‌کند.

**توزیع واقعی لینک و اعتبار:**
- **۱۸۵** مورد جدید: URL فهرست/دسته مرتبط (collection)، نه آدرس دستور خاص.
- **۸** مورد جدید: URL یک دستور مشخص (recipe)؛ هنوز مقادیر و روش با مقاله تطبیق و پخت عملی تأیید نشده.
- **۱۳** مورد جدید: تغییر/اقتباس مستقل (adaptation)، نه ادعای بازتولید خود دستور منبع.
- **۱۶** مورد قدیمی: URL مرجع از قبل موجود، بدون برچسب سطح مرجع و تأیید فعلی.
- **۱۵۶** مورد قدیمی: داده تدوینی بدون URL مشخص.
- **۳۷۸ از ۳۷۸**: وضعیت `draft`؛ هیچ رکورد `reviewed` وجود ندارد.

نمونه صفحات کشف: `https://tollbit.bbcgoodfood.com/recipes/collection/quick-chicken-recipes`، `/vegetarian-pasta-recipes`، `/pasta-recipes` و `https://chishi.ir/20064-ghaza-irani/`. URLهای مرجع در هر رکورد ثبت شده‌اند؛ وجود نام مشابه در این صفحات، **تأیید نسبت دادن مواد و مراحل نوشته‌شده به مؤلف منبع نیست**. ۱۶ غذای پیچیده ایرانی مراحل مستقل و اختصاصی دارند؛ سایر موارد عمدتاً دستورالعمل‌های چهارمرحله‌ای الگو-محورِ مناسب نوع پخت هستند و **برای پخت بدون خطای عملی به بازبینی انسانی نیاز دارند**. به همین علت هدف «تعداد دو برابر» محقق است، اما هدف «۳۷۸ دستور واقعی و تأییدشده همان سایت‌ها» هنوز محقق نشده است.

## اصلاحات داده‌ای و الگوریتمی

۱. افزودن ۷۸ نام ماده و Aliasهای فارسی، تطبیق برخی واحدهای حجمی/شمارشی و ثبت ترکیبات فرآوری‌شده دارای برچسب نامطمئن. فیلتر آلرژن در برابر مواد با ترکیب تأییدنشده محافظه‌کار است.

۲. بررسی شناسه یکتا، مقدار مثبت، نام/مواد متناسب، رد تشابه مجموعه مواد کاملاً یکسان در دو دستور جدید، داشتن حداقل چهار مرحله در رکوردهای جدید و یادداشت حداقل دمای گوشت/مرغ/ماهی. این‌ها **تست‌های ماشینی ساختاری** هستند و تأیید پخت، سلامت یا مجوز محتوایی نیستند.

۳. مهاجرت SQLite از v4 به v5 با جداول `catalog_recipe_search` و `catalog_ingredient_alias`، ایندکس فارسی، صفحه‌بندی، جست‌وجوی پارامتردار و ورود دسته‌ای. ارتقای شماره محتوا `2026102003`. جدول‌های داده کاربران به‌طور مستقل نگهداری می‌شوند؛ تست واقعی ارتقا روی OP-SQLite اندروید هنوز اجرا نشده.

۴. صدور `content/seghalam-catalog.sqlite` برای بازرسی SQL، JSON خام و صف بازبینی CSV با هش SHA-256. تغییر متن یک رکورد، تأیید قبلی آن را باطل می‌کند.

## اندازه و عملکرد

- حجم فایل کاتالوگ SQLite برای بازرسی: **۱٬۵۲۳٬۷۱۲ بایت (~۱٫۴۵ MiB)**؛ JSON: **۱٬۰۲۴٬۸۸۳ بایت (~۱٫۰۲ MB)**؛ این مقادیر حجم نصب APK نیستند.
- میانه بنچمارک **SQLite روی سیستم میزبان**: صفحه ۲۴ رکوردی **۰٫۰۲۴۵ ms**، جست‌وجوی عنوان `LIKE` **۰٫۰۵۰۶ ms**، Alias **۰٫۰۰۴۴ ms** (ابزار `scripts/profile_catalog_sqlite.py`). این اعداد سرعت گوشی یا هزینه JSON parsing/JSI را اندازه نمی‌گیرند و برای وعده FPS یا سرعت دستگاه قابل تعمیم نیستند.
- کل کاتالوگ هنوز در ابتدای اجرا از داده بسته‌شده به SQLite وارد و بعد در حافظه JavaScript کش می‌شود. برای همین دامنه ۳۷۸ دستور معمولاً از نظر حجم کوچک است، ولی Cold Start واقعی، RAM، UI scroll، اندازه Bundle و رشد آینده باید روی گوشی ارزیابی شوند.

## شواهد تست و مانع انتشار

- **۶۲ از ۶۲ تست Node PASS**؛ `audit:semantic`، کنترل ساختار داده و SQLite Foreign Keys و شبیه‌سازی مهاجرت v4→v5 با حفظ داده‌های کاربر PASS؛ گزارش در `docs/TEST_REPORT.md`.
- `npm run audit:content` **عمداً FAIL**: هیچ‌یک از ۳۷۸ دستور هنوز بررسی مستقل ندارند.
- Typecheck کامل RN و Build/Debug APK و تست Android E2E **در این محیط انجام نشده**؛ وابستگی‌های React Native، Android SDK و Wrapper آماده نیستند.
- امنیت آلرژی شدید، کالری/تغذیه، وزن‌ها و روش دقیق پخت، عکس و لایسنس محتوا، و رتبه‌بندی واقعی روی دستگاه هنوز نیازمند تأیید هستند.

## پرونده‌های قابل بازتولید

`content/researched-recipes.psv` (منبع ویرایشی) → `scripts/compile_research_recipes.py` → `src/data/researchedRecipes.ts` → `npm run test:all` → `content/catalog.generated.json` → `content/seghalam-catalog.sqlite` → `content/editorial-review-queue.csv`.

**اولویت واقعی برای Production بعدی:** ۱) یافتن لینک دقیق برای هر دستور، ۲) تطبیق و اصلاح مواد/مقادیر/روش با آن صفحه بدون کپی متن، ۳) تست پخت و ممیزی آلرژن/مجوز توسط انسان، ۴) تأیید موارد در CSV و تغییر وضعیت در سورس، ۵) تست migration و جست‌وجو روی اندروید و سنجش FPS/RAM، ۶) Build و Signing.
